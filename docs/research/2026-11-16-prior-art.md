# Prior art: what other open players can teach the renderer

The import already reads the project file, and expressions are baked at import ([D38](../design/decisions.md#d38-expressions-are-baked-at-import), [expressions note](2026-11-14-expressions.md)). What keeps most templates from matching their reference is drawing: adjustment layers, effects, 3D and the camera, motion blur. This note asks which open projects already draw these, under which licence, and what each one can give us.

Nothing here is code to copy. Each source is a reference for behaviour: which parameters matter, how the original maps them, and what an open player chose where the original is undocumented.

## What still blocks the corpus

Measured on 2026-11-16 over 154 of the 198 local templates, with a build of `main` plus the open shape pull requests (merge, expansion, round corners, repeater, content size). Each row counts the templates the import reports it for.

| Expressions it could not bake | 31 |

| Directional blur (the effect named "Motion Blur") | 13 |
| Text: expression selectors | 13 |
| Text: scaled characters | 13 |
| Text: kerning other than the font's | 11 |
| Composite (a third-party effect) | 9 |
| Laser | 8 |

Fonts are not a drawing problem, and expressions have their own note. The rest is text animation and about twenty effects, none in more than 13 templates.

## Who reads the project file

| Project | Language | Licence | What it does |
|---|---|---|---|
| `aep_parser` and `py-aep` (forticheprod) | Python | MIT | Read the file into an object model shaped like the application's scripting API. They do not evaluate expressions. We use its format description as our spec. |
| `aftereffects-aep-parser` (boltframe) | Go | MIT | Reads the file's structure. We use its fixtures. Last changed in 2022. |
| `aepx.js` | JavaScript | | Reads the XML variant. Deprecated by its author. |
| Glaxnimate | C++ | GPL-3.0 | Imports the project file into its own editor (0.5.4, 2023). |

No Rust reader exists, and none of these draw what they read. Glaxnimate is the only one that imports into a renderer, and its licence rules its code out ([D13](../design/decisions.md#d13-codec-licence-policy)).

## Who draws the same features

All four are Lottie players. Lottie is the application's own animation model, exported, so its fields map one to one onto what our import decodes.

| Feature | Skia's player (BSD-3) | ThorVG (MIT) | velato (MIT or Apache-2.0) | Lottie web player (MIT) |
|---|---|---|---|---|
| Effects | 28 (below) | Fill, Stroke, Tint, Tritone, Drop Shadow, Gaussian Blur | Fill, Tint, Drop Shadow, Gaussian Blur, through a custom sink | Fill, Stroke, Tint, Tritone, Levels, Drop Shadow, Gaussian Blur, Transform, Set Matte |
| Track mattes | alpha, luma and inverses | alpha, luma and inverses | in progress (unreleased) | not checked |
| Masks | add, subtract, intersect, difference; feather | add, subtract, intersect, difference, lighten, darken; expansion | not checked | add; inverted |
| Adjustment layers | skipped | not listed | not listed | not listed |
| 3D and camera | one- and two-node camera, zoom, X/Y/Z rotation, auto-orient | not listed | not listed | not checked |
| Layer motion blur | not found | not listed | not listed | no |
| Blend modes | all 16 standard ones, add, hard mix | engine only | not checked | not checked |
| Time remap, stretch | precomps | yes | in progress | yes |
| Expressions | host hook only | JerryScript, opt-in | no | `eval` |

Skia's player maps these effect names to builders, in `modules/skottie/src/effects/Effects.cpp`:

> Black & White, Brightness & Contrast, Bulge, CC Sphere, CC Toner, Corner Pin, Displacement Map, Drop Shadow, Easy Levels, Fill, Fractal Noise, Gaussian Blur, Gradient Ramp, Hue/Saturation, Invert, Linear Wipe, Directional ("Motion") Blur, Pro Levels, Radial Wipe, Sharpen, Shift Channels, Threshold, Motion Tile, Tint, Transform, Tritone, Venetian Blinds; plus layer styles (stroke, drop and inner shadow, outer and inner glow, colour overlay).

It does not implement Glow, Curves, CC RepeTile or Turbulent Displace. Neither does any other open player we found.

## What each source gives us

| Gap | Templates | Who has it | What to take |
|---|---|---|---|
| Random order | 21 | Skia's player | It shuffles the selector's domain with a fixed seed (Mersenne Twister, 42). The original's generator is unpublished, so ours is approximate either way, as for `wiggle`: a fixed, documented seed and an *approximate* mark in the report. |
| Anchor point grouping | 18 | Skia's player | Character, word, line and all, with grouping alignment as a percentage of the group's box. Each part's matrix turns and scales about its group's anchor. This is the reference for our grouping. |
| Directional blur | 13 | Skia's player | Its directional blur, which it maps this effect to: the parameters it reads and how blur length becomes a kernel. |
| Set Matte | 7 | Lottie web player | `SVGMatte3Effect`: which layer it takes, which channel, invert, and "stretch to fit". |
| Layer styles | 5 | Skia's player | Drop and inner shadow, outer and inner glow, colour overlay, stroke: the parameters each style reads. |
| Stroke (the effect) | 5 | ThorVG, Lottie web player | Painting along a mask path: brush size, hardness, start and end, spacing. |
| Linear Wipe | 4 | Skia's player | The wipe angle and feather. |
| Tritone, Threshold, Brightness & Contrast, Shift Channels, Corner Pin, Radial Wipe, Bulge | 0 to 3 | Skia's player | Cheap to add from its parameter mapping when a template needs them. |
| Text blur, tracking | 6 | Skia's player | Its text animator binds `bl` (blur) and `t` (tracking); how it spreads them over a selection. |
| Expression selectors | 13 | none | Skia's player ignores them. Our expression engine can evaluate them per part; the import does not run them yet. |
| Laser, Minimax, Wave Warp, Emboss, Roughen Edges, Noise, Simple Choker, Twirl, Colour Balance, Camera Lens Blur | 4 to 8 each | none | No open player has them. Their behaviour comes from the application's documentation, checked against the reference renders. |
| Composite | 9 | none | A third-party effect; reported, not drawn. |

**Licences.** Skia's player is BSD-3, ThorVG and the Lottie web player MIT, velato MIT or Apache-2.0. All allow reading and porting with attribution ([D9](../design/decisions.md#d9-licence)), though we take behaviour, not code: their structure does not fit ours. Glaxnimate is GPL-3.0, so we neither read nor port its import ([D13](../design/decisions.md#d13-codec-licence-policy)).

**Test material.** Each player keeps small Lottie files per feature. They are not references for fidelity (only the original application's render is), but they make good unit inputs for the parts of the drawing that are the same in both models: path operators, selectors, mattes.

## Where we already stand

Our renderer already draws, from the scene format: adjustment and filter layers, alpha and luma mattes, all standard blend modes, masks with feather and expansion ([D55](../design/decisions.md#d55-masks-are-items-that-cut-a-layers-content-before-its-effects)), motion blur over the shutter ([D57](../design/decisions.md#d57-motion-blur-samples-a-layers-motion-over-the-shutter)), 2.5D layers through a camera ([D58](../design/decisions.md#d58-25d-layers-are-planes-projected-through-a-camera)), time remapping ([D62](../design/decisions.md#d62-a-layer-may-remap-the-time-of-its-content)), and 29 effects, Glow, Curves, Turbulent Displace and Repeat Tile among them.

- **No open player draws adjustment layers or layer motion blur.** Skia's player skips adjustment layers; the others do not list them.
- **No open player has Glow, Curves, Turbulent Displace or Repeat Tile.** For these our only check is the reference render.
- **No open project reads the project file and draws it, in any language.**

So the open players are no longer ahead of us on features. What they still offer is narrower: the effects we lack, and a second opinion on constants the original does not document.

## A second reader as a check

Glaxnimate's code is ruled out, but running it is not: its export can be compared with our reader's output without any of its code entering ours. We ran Glaxnimate 0.6.0 headless (`--export … -f lottie`) on every local template and compared, layer by layer, the transform values our reader decodes with the ones it writes. The comparison printed counts only.

- **Coverage:** it opened 181 of the 198 templates (13 fail with "not enough data", the rest on missing assets or a text document). In those, 1,704 compositions and 3,666 layers matched by name and order, and 6,701 transform channels were compared: anchor, position, scale, rotation and opacity.
- **Values agree.** Once units are aligned (we keep scale and opacity as fractions, and a footage layer's anchor as a fraction of its source), every static value and key value matched but four. Those four sit on layers whose parenting Glaxnimate rewrites.
- **Every other difference is Glaxnimate's own conversion,** not a decoding difference:
  - it writes the frame rate as a whole number (29 for 29.97) but counts frames at the true rate;
  - it drops a layer's start time;
  - it adds keys (one halfway along a segment, or a second key at the same time);
  - it adds wrapper layers, so 938 compositions have a different layer count.
- **Conclusion:** our reader's transform decoding agrees with an independent reader. Glaxnimate is no better an oracle than that: its model is Lottie's, so it cannot check effects, text animation or 3D, which the reference renders already check. We do not keep it as a tool.

## Recommendation

1. **Text animation first.** Grouping, random order, blur and tracking touch more templates (18 to 21 each) than any effect, and Skia's player covers all four. One plan for the text animator, with its grouping as the reference.
2. **Then the effects with an open reference,** by templates: directional blur, Set Matte, layer styles, Stroke, Linear Wipe. Each is a row in the effects table and a test against a reference render.
3. **Then the effects nobody has open,** by templates: Laser, Minimax, Wave Warp, Emboss, Noise. Their behaviour comes from the application's documentation, checked against the reference renders.
4. **Re-measure the whole corpus** after each group, and update the counts here.

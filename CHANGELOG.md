# Changelog

All notable changes to this project are documented here. The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this project follows [Semantic Versioning](https://semver.org/).

The project was named motion until 2026-11-17, when it became nakkash ([D73](docs/design/decisions.md#d73-the-project-is-named-nakkash)). Entries written before then keep the old name, crate names and commands as they were written.

## [Unreleased]

### Added

- Instances ([D91](docs/design/decisions.md#d91-an-agent-fills-a-template-through-a-pinned-instance-a-brief-and-one-merge-point)): an agent fills a template with a small file of slot values, `{"schema":"nakkash.Instance.1","template":{"path":"promo.json","hash":"sha256:…"},"slots":{"headline":"Jeden Markt"}}`. `render`, `check`, `vary`, `batch`, `export`, `at` and `slots` read it as the scene it makes: `Session::open` merges it, the session reads the template's files from the template's folder, and it refuses to save, so the template is never written. `slots` is a patch keyed by slot id (`comp/id` for a composition's), with `{"$unset":true}` and `{"$hide":true}`. `look` chooses one of the template's `looks`, `sections` names what each root `comp` layer is for, and `raw` sets static values no slot holds, never motion, timing, effects or drawn paths. The template is pinned by the SHA-256 of its canonical form (`nakkash_format::canon`, `nakkash.Canon.1`) and by each written slot's `uid`. A changed template is a warning while every written slot is still there; a slot found under another id by its uid or an alias is relinked, and one that is gone is stale. Merging runs in stages, *parse*, *resolve* and *type*, and each returns every problem at once as `{"level","code","stage","slot","path","message","rule","measured","limit","hint"}` (`nakkash_edit::instance`). A stage with an error stops the next, and an instance with an error does not render. New commands and options:
  - `nakkash check <instance> [--json]` prints the problems, then what the scene adds to its template's check.
  - `nakkash edit <instance> '$id=value' … 'look=light'` writes the instance only when nothing is refused, and leaves out values equal to the template's.
  - `nakkash slots <template> --as-instance [--all] [--out FILE]` writes a pinned instance.
  - `nakkash migrate <instance>` pins an instance again, with relinked slots under their new ids and lost ones kept under `stale`.
  - `nakkash brief <template|instance> [--json]` prints what an agent fills: rules and locks first, then sections with story roles, text budgets, colours with pairs and contrast, typed media and choices.
  - A fourth stage, *measure*: `text.overflow`, `text.shrunk`, `color.contrast`, `media.small`, `media.crop`. `check` on a template warns where its own values break these contracts.
  - `docs/guide/fill-a-template.md`, also the `nakkash-template` skill.
  - `nakkash edit` on a scene takes several lines, applied in order.

  An example template and instance are in `examples/instance/`.
- Slot declarations say what an instance may give them ([D91](docs/design/decisions.md#d91-an-agent-fills-a-template-through-a-pinned-instance-a-brief-and-one-merge-point)): `choice` slots, a word from `values` that any string can follow (`"comp":"$ending"` chooses a section); `min` and `max` on numbers; `overflow` (`shrink`, `wrap`, `reject`), `min-size` and `max-lines` on texts; `pair` and `contrast` on colours; `kind` (`screen`, `logo`, `image`, `video`, `texture`), `accepts`, `min-px` and `aspect` on files; and `uid` and `aliases` on any (`Slot::uid`, `Slot::contract`, `Contract`, `Slot::fits`). A slot's own value stays inside its bounds, and an override or a look that does not is an error. A scene's `looks` are named sets of slot values.
- Styles, eases and defaults left out ([D91](docs/design/decisions.md#d91-an-agent-fills-a-template-through-a-pinned-instance-a-brief-and-one-merge-point)): a scene's `styles` are named sets of layer keys, which a layer takes with `"inherits":"<name>"` or a list of names, the later winning and the layer's own keys winning whole; its `eases` are named curves that the `curve` of a key written as an object may name, under a name that does not already read as a curve. Both are expanded on a copy before slots resolve, so a styled scene reads as the same `Scene` as the scene written out, and the document keeps what was written; the slot listing, `layer_json`, `resolved` and the colour places read through styles. An edit inside a key a layer only inherits starts from the style's value, and removing such a key is refused. `nakkash compact scene.json -o out.json` writes repeated effect stacks and animations as styles (`fx-glow-box-blur-levels`, `anim-position-opacity`), repeated `speed(…)` and `cubic(…)` curves as eases named by their shape (`still-to-stop-95-97`) and leaves out values at their fixed rest, then reads the result back and writes it only when it is the same scene: a row whose default the reader keeps as written (on an imported 28 s promo: `rotate`, `scale`, `scale-z`, `anchor-z`, `target-z` and the `transform` effect's `opacity`) stays written and is named in the report, and a part that would still change the scene is left out. A snapshot of the format's defaults table (`crates/nakkash-format/tests/defaults.rs`) guards them, and a compatibility scene, `v1/styles`, uses the new keys.
- The `corner-pin` effect ([D89](docs/design/decisions.md#d89-a-corner-pin-lays-its-layers-plane-through-a-homography)): the layer's box laid onto four corners through the homography that takes it there. Each corner (`top-left`, `top-right`, `bottom-right`, `bottom-left`) is the px it moves from where it rests: the box's corner, or with `"pivots":"screen"` the corner pivots `screen-tl` … `screen-bl` that `nakkash ml track --corners` writes, or any four layers of the list (`"pivots":["a","b","c","d"]`), each where it lands seen from the pinned layer. Evaluation resolves every pin into the node's state (`NodeState::pins`, `nakkash_scene::pin`), so the render, `check` and motion blur read one quad. The rasteriser draws the layer's content, masks and earlier effects as a plane at twice the size the pin lands them (`Apply::Pin`, `Plan::pinned`), laid with a new box filter (`Filter::Box`: each px the mean of the parallelogram it covers, from a grid of bilinear probes on the copy finer than half its footprint), on the CPU and in the GPU's projection kernel; later effects run on the pinned result, a pin on an adjusting layer pins what is below on its grid, and `mblur` lays the pin through its corners at each moment, paired with the layer's moves (`Effect::with_moments`). Against a supersampled reference, pinned 14 px text shrunk about four times into perspective is off by a mean of 0.0166 (moving pixels as the other distortions do: 0.1023) at 0.92 of the reference's sharpness (aliased, 1.51), and 7 px text enlarged three times by 0.0025 (0.0884) at 1.02 (blurred, 0.45). A quad that is crossed, bent, flat or out of the layer's sight draws nothing and is the new `check` error `pin`. The import maps `ADBE Corner Pin`, which it reported. `Homography::from_quad` makes the map, and `nakkash_format::item::CORNER_SUFFIXES` names the corner pivots for both the track and the pin.
- Learned models in a bake ([D80](docs/design/decisions.md#d80-learned-models-run-in-a-bake-never-in-a-render) to [D88](docs/design/decisions.md#d88-a-track-is-baked-once-and-applied-as-keys-on-pivots)), behind the CLI's `ml` feature: `nakkash ml models list | fetch | import | verify` keep the inference runtime and the model files the model lock pins, by hash. `nakkash ml preview <scene>` segments what each video layer's `cutout` and `tracks` ask for, follows a track's points, and writes a contact sheet per request. `nakkash ml bake <scene>` bakes every request whose bake is missing or stale, writes the `baked` digests into the scene, and keeps the segmentation of each set of prompts in a work cache, so a preview followed by a bake segments once. `nakkash ml track <scene> <layer>.tracks[<id>] --to <pivot> [--corners]` writes a baked track as keys on a pivot parented to its video layer. `Session::replace` takes a scene's JSON changed by a tool, once it validates.
- Baked cutouts on video layers ([D85](docs/design/decisions.md#d85-baked-results-enter-the-scene-as-requests-on-video-layers)): `cutout` asks for the layer's object, cut out of its clip from prompts on its frames, and `tracks` for motion tracks of objects in it; `nakkash ml bake` will write their `baked` digests. The render multiplies each clip frame's alpha by the baked alpha of the same frame, read from the `baked` folder of the cache and opened only when it answers the layer's request for this clip, by the clip's hash; an unbaked cutout, a digest the cache lacks, or a bake of other prompts or another clip is an error at `cutout` that names `nakkash ml bake`. A new crate, `nakkash-baked`, holds the assets; the SHA-256 type moves to `nakkash-format`. Clips give their frames by index (`Clip::frames`, `shown_at`, `frame`, `start`), and `Session::baked_store` names the store.
- Unseen slots: `nakkash slots --verify --mark` writes `"seen": false` on each slot that changes nothing drawn and clears it on each that changes the render; variants leave marked slots as they are, and `nakkash slots --coverage` counts them, `unseen slots 3/40`, a measure of what the renderer does not draw yet.
- Every imported template names what a designer would vary ([D77](docs/design/decisions.md#d77-every-imported-template-names-what-a-designer-would-vary)): each text layer's words, a palette of its colours, each footage file and its length become slots, each with a role, and the values follow them. Texts take a role from their name, their words and their size, and a `fit` of the size their lines cover, measured in the scene's own fonts; colours within 0.04 in OKLab are one entry, its near-duplicates changed references to it; footage the scene cannot draw is an `image` or `video` layer of `null`, with its box; compositions named for editing come first. Composition markers become `labels`, the model reads a composition's own markers (`Composition::markers`), and the import writes no default locks. The report says `slots to vary: N text, N colour, N media, N timing`. `Options::plain` leaves the slots out.
- Slot kinds for templates ([D77](docs/design/decisions.md#d77-every-imported-template-names-what-a-designer-would-vary)): `image` and `video` slots, which may be `null` for no file yet; a `role` beside a slot's `label`; a reference that changes a colour slot in OKLCH, `"$accent l-0.021 c+0.004 h+1.6 / 0.5"`, so near-duplicates and translucent copies of a palette colour move with it; and `bg` and `dur` that follow slots. An export compares scenes with their references resolved, so a slot's new value goes back at every value that follows it.
- `nakkash slots --coverage` counts the text layers, colours and footage no slot holds, and `nakkash slots --verify` changes every slot alone, draws it where it shows and reports each that changes nothing, then checks the scene with all of them changed.
- Media layers a variant can refill ([D77](docs/design/decisions.md#d77-every-imported-template-names-what-a-designer-would-vary)). Image and video layers take `fit`: `fill`, the default and what they drew before, stretches the picture over its box; `contain` keeps the picture's proportions inside the box, centred; `cover` keeps them and fills the box, centred and cut by it. The proportions are the `crop`'s, or the whole picture's: raster pixels, a vector page or a clip's frame. The box stays the layer's box for layout, its anchor and `check`, so a fit only moves where the picture is drawn inside it, at render time. A picture within one unit of its box across and down draws exactly as `fill`, so `"fit":"contain"` on a box written in whole units over its own footage leaves the drawing bit-identical. `"image": null` and `"video": null` are layers with their box and no file yet: they draw nothing, read nothing, and pass `check`. An unknown fit is an error at `fit` listing the three, and a fit on any other layer but text an error at `fit`. A compatibility scene, `v1/fits`, holds them. `ImageContent::path` and `VideoContent::path` are now `Option<String>`, and both carry a `MediaFit`.
- Text that fits its size: a text layer's `fit` keeps longer words inside the size the text was laid out for, as when a slot replaces them ([D77](docs/design/decisions.md#d77-every-imported-template-names-what-a-designer-would-vary)). `"shrink 600x300"` scales every size in point text down until its lines fit 600 by 300 px, about their vertical middle; `"wrap 600x300"` breaks point text's lines at 600 px, each aligned about the origin, and shrinks it, keeping its top, when it is taller than 300; `"shrink"` shrinks box text until its wrapped lines fit its box. Sizes, leading in px, baseline shift, stroke width, indents and paragraph spacing scale together. The factor is found by bisection on the real layout, within 0.1 % of the largest that fits, and a text never grows. A text without `fit`, or one that fits, lays out exactly as before: the compatibility corpus's snapshots do not move, and a new scene, `text-fit`, uses the key. `nakkash_engine::written_text_size` gives a text layer's size as written, its fit left out, which is what an import writes as the fit's size.
- Animated curves: the import writes a keyed `curves` effect as tracks of its `rgb`, `red`, `green`, `blue` and `alpha` paths, where it kept the first key and reported the rest. Keys may hold different points; the import puts every key on the inputs of all of them, so the scene moves from key to key point by point, which is the original's move from one curve's levels to the other's. Between a key's own ends the spline on more inputs is the key's spline exactly; an input beyond a key's end takes the level that keeps its curve closest, by least squares, and a key whose curve that strays more than one 8-bit level, or keys with more than 16 inputs together, are still reported, with the stray ([evidence K1–K3](docs/design/aep-evidence.md#animated-curves)). The natural cubic spline of the curves moves to `nakkash_format::spline`, shared by the import and the rasteriser.

- The `lens-distortion` effect: the layer bent about `center` as a wide lens draws it, a lens that draws a ray at angle φ from its axis f·sin φ from it where a pinhole draws it f·tan φ away, its focal length set so that `field-of-view` degrees span the box's width, height or diagonal (`field`). `add` draws the layer as that lens sees it; `remove` undoes the lens, stretching the layer out from its axis. With `grow` `2x` or `4x` the box grows to hold what it draws, up to twice or four times its size about its middle, through a new kind of growth, `Growth::To`, worked out from the box (`Reach::Grows` now holds a `Growth`). - The `color-cycle` effect: each pixel's phase, a level of its straight colour (`phase-from`), joined by a level of the `add` layer (`add-from`, `add-mode`), repeated (`repetitions`) and shifted (`shift`), runs round a cycle of colours, four curves of the phase (`red`, `green`, `blue`, `alpha`) joined from point to point and round the turn, or held (`interpolate` `off`). The cycle's colour replaces the channels `modify` names, its alpha multiplies the pixel's (`modify-alpha`), and `blend` keeps some of the original ([evidence Y1 and Y2](docs/design/aep-evidence.md#colour-cycles)). The import maps the project's colour cycle effect, reading its stored stops into the curves; it reports pixel selection, masking by a layer and colouring empty pixels. Levels read a pixel's intensity and value too.
- The `set-matte` and `shift-channels` effects. `set-matte` takes the layer's alpha from a level (`channel`: a colour, `alpha`, `luminance`, `hue`, `lightness`, `saturation`, `full` or `off`) of the layer `matte` names, laid on the layer by their effect boxes, stretched (`behaviour` `stretch`) or centred (`center`); `inverted` turns it over, `composite` `off` replaces the layer's alpha instead of multiplying it, and `premultiply` `off` reads the matte's own colour rather than its colour over black. Without `matte` it reads the layer's own drawing before its effects ([evidence S1 to S3](docs/design/aep-evidence.md#mattes-from-other-layers)). `shift-channels` rebuilds each channel from a level of the layer's straight colour (`alpha-from`, `red-from`, `green-from`, `blue-from`). The import maps the project's matte and channel-shift effects to them, every parameter, where it reported both as unsupported; a switched-off one is kept hidden. An effect input may now be read laid (`Reads::Laid`): the engine lays the layer it reads on the reading layer's effect box, a shape's or text's being its composition's size about its origin, and a collapsed composition's the canvas it draws into, so nothing it reads falls outside the frame. The displacement map reads its levels through the same `Level` reader (`channel.rs`) and lays its map through the same `Lay`.

- Two fractal types of `fractal-noise`, `smeary` and `swirly`: each octave after the first is sampled at a point moved by the level of the octaves before it, along the noise's own x axis by up to a cell either way (`smeary`), or half a cell in a direction that turns once around as that level runs from 0 to 1 (`swirly`), so the detail follows the larger shapes. - The `radial-blur` effect: each pixel the mean of the layer along the line through it that runs out from `center` (`type` `zoom`) or round it (`spin`), over `amount` percent of its distance from the centre or `amount` degrees, from the pixel back towards the centre or clockwise (`stretch` `behind`) or half either side (`across`), its pixels weighing alike or fading to none at the far end (`fade` `linear`). The mean is taken over the whole stretch from running sums along rays and rings one px apart, so its cost does not grow with the streaks: about 0.7 s of one core for a 3840 by 2160 layer. The import maps `CC Radial Blur` to it, every type but `Scratch`, which is reported, with Amount / 2 as the amount ([evidence R1 and R2](docs/design/aep-evidence.md#radial-blurs)), and the spin of `ADBE Radial Blur`; its zoom, whose amount's scale no sample shows, is reported and drawn as no blur. A row may now set several settings from one property (`To::Settings`).

- The `bezier-warp` effect: the layer's box laid on a patch bounded by four cubic curves, each side running from corner to corner through its two handles, filled between them as a Coons patch. Each of its twelve points is the px it moves from where it rests, on the box's corners or a third of the way along its sides, so at rest nothing moves; it grows the box by as far as any point moves past it. The import maps `ADBE BEZMESH` to it, where it was reported and dropped, each point the px it moves from its parameter's default (`Convert::FromRest`), and ignores its quality, which only shows as facets ([evidence D9](docs/design/aep-evidence.md#distortions)).

The import maps the project's linear and iris wipes to them, every parameter, where it reported both as unsupported.

- The `vector-blur` effect: the layer smeared along the slope of one level of a `map` layer, or of its own drawing: the level softened by `softness`, its slope by `ridge-smoothness` so streaks shorten along ridges instead of flipping, and each pixel the mean along a straight streak turned `angle` degrees from the slope, `amount` px at the steepest (`natural`), always (`constant-length`), across the slope (`perpendicular`), or behind the pixel only (`direction-center`, `direction-fading`). The import maps `CC Vector Blur` to it ([taken without evidence](docs/design/aep-evidence.md#vector-blur)): no corpus sample holds one, so it is checked on synthetic maps only.
- The `find-edges` effect: where the colours change, drawn as lines, by each colour channel's Sobel slope over the 3×3 frame pixels around each pixel, scaled so a step from 0 to 1 gives 1. `lines` draws them `dark-on-light` or `light-on-dark`; alpha stays, and `blend` of the layer as it was shows through. The import maps `ADBE Find Edges` to it, its Invert as `light-on-dark` ([evidence G1](docs/design/aep-evidence.md#found-edges)), where it was reported and dropped.

- The `lens-blur` effect: each pixel the mean of the layer over a lens's iris about it, a polygon of three to ten sides (`iris`) with its corners `radius` px out, bowed `roundness` of the way to a circle, `aspect` times as wide as high and turned `rotation` degrees; an odd-sided iris spreads as it stands, not upside down. With a `map` layer each pixel's radius is `radius` times how far its `map-level` (taken from 1 when `inverted`) is from `focal-distance`, the map centred on the layer or stretched over it (`placement`); `edges` `repeat` repeats the edge pixels beyond the frame. The iris is read a row of pixels at a time from running sums, so a pixel costs two reads a row it spans and its edges fall between pixels, growing smoothly with the radius. The import maps `ADBE Camera Lens Blur` to it ([evidence L1](docs/design/aep-evidence.md#lens-blur)), and reports a gain on its highlights, a diffraction fringe other than 100 and its unnamed switch turned off, which no sample shows.

- The `bevel` effect: the layer lit as if its alpha rose from its outline over `thickness` px, flat beyond, by light of `color` from `angle` degrees clockwise from up. A slope facing the light goes towards its colour and one facing away towards black, by `intensity` times how squarely it faces it; alpha stays. The distance in from the outline is an exact Euclidean distance transform of the frame's pixels (a new module, `light.rs`). The import maps `ADBE Bevel Alpha` to it, where it was reported and dropped ([bevels](docs/design/aep-evidence.md#bevels): taken without evidence).

The level is that of an `audio` or `comp` layer of the same list over a frame's window, as the mix plays it: RMS, or the loudest part of a band of the spectrum, smoothed by a one-pole filter. The curve shapes it. The engine measures it once a frame from a first compile's routes and compiles again with the track keyed every frame (`motion_scene::compile_with`, `Levels`, `Hearing`; step `listen`), so any frame evaluates alone. Layer and item tracks may listen; `volume` may not.
- Motion blur ([D57](docs/design/decisions.md#d57-motion-blur-samples-a-layers-motion-over-the-shutter)): a layer with `"mblur":true` is drawn as the average of its drawings at moments over its composition's `shutter` (`"180 -90 16"` by default, `motion_format::shorthand::Shutter`). A layer that moves far takes up to 8 times the samples. A `comp` layer, or one with effects, is drawn once and moved to each moment, up to 2 times the samples, so nested compositions don't multiply the cost. The engine evaluates each canvas at those moments once per frame and adds the samples at `1/n` each in a group of their own, which then takes the layer's blend, opacity and matte.
- The import plays sounds (audio plan step 6): found audio footage becomes an `audio` layer, sniffed for its format by the engine (`motion_import::map::Sound`, `Options::sounds`). Audio levels become `volume`, keyed every frame where they move, since the original moves in decibels. The layer's audio switch, now read from the project (`Switches::audio`, printed by `inspect`), mutes audio layers and composition layers that play a sound. Audio Spectrum becomes `audio-spectrum`, reading its Audio Layer. Audio Waveform still draws nothing until a project shows its parameters.
- `audio-spectrum` and `audio-waveform` effects ([D56](docs/design/decisions.md#d56-audio-layers-mixed-at-48-khz-and-read-by-effects), audio plan step 5): they draw the sound of the audio layer, or of the composition behind the `comp` layer, that `audio` names: a window `duration` ms long about the layer's time, as the mix plays it. The spectrum shows `bands` frequencies from `from` to `to` Hz, from our own FFT, and the waveform `samples` points of the wave, as squares, bars, lines or dots along a line or round a circle, coloured from `inside-color` to `outside-color` across each stroke. An effect kind now says whether its input is read as a drawing or as a sound (`motion_format::item::Input`), and the format rejects a sound read from a layer that plays none and a drawing read from an audio layer. Defaults follow the original effect: `height` 480, `to` 2000 Hz, `side` `both`.
- Audio layers and the mix ([D56](docs/design/decisions.md#d56-audio-layers-mixed-at-48-khz-and-read-by-effects), audio plan step 2): `"audio":"music.mp3"` plays a sound file in the layer's own time. `offset` starts it, `span` trims it, `stretch` plays it slower and lower, and `hidden` mutes it. The new `volume` property (1 as recorded, up to 4) fades it with keys; on a `comp` layer it scales the composition's sound. An audio layer takes no effects or matte and mattes nothing. `motion_scene::routes` finds every audio layer through its compositions, and `Route::at` says what it plays at any frame. `Session::mix` mixes the scene into stereo at 48 kHz: what each layer plays is asked once a millisecond and moved in a straight line in between, and a layer starts on its own sample. `motion render scene.json --out mix.wav` writes the mix and says when it goes above full scale.
- `motion-audio` ([D56](docs/design/decisions.md#d56-audio-layers-mixed-at-48-khz-and-read-by-effects), audio plan step 1): reads sound files, by their first bytes. WAV (PCM 8 to 32 bits, float, A-law, µ-law, extensible, RF64) is our own reader; MP3, FLAC and Ogg Vorbis go through pure Rust decoders. Each file becomes a `Sound`: its channels and where their speakers stand. `Sound::for_mix` folds a sound down to stereo (ITU-R BS.775) and resamples it to 48 kHz with our own Kaiser-windowed sinc kernel (`Kernel`). `wav::encode` writes a mix. Each format matches ffmpeg's decode of the test files: exactly for WAV and FLAC, within 2e-4 for MP3 and 1e-5 for Vorbis. A three-minute 44.1 kHz MP3 decodes in 0.08 s and is laid out for the mix in 0.18 s.

Footage it cannot find, video, image sequences and audio are reported with why. `motion_engine::import_scene` takes where the scene will be saved, so footage paths are relative to it.

- `motion-expr`: expressions compile once and run at any time over a host (comps, layers, properties, keys), with the language's array arithmetic, interpolation, loops, vector and colour functions, the legacy engine's forms, deterministic maths and randomness, and a fitter that turns per-frame samples into a few keys within a tolerance. Every distinct expression of the local corpus compiles (D38).
- `motion import` bakes expressions (D38): each one switched on is evaluated at every frame its layer shows, where the scene shows its comp, over the project read as the language sees it (comps, layers, groups, properties, effect parameters at their default, a layer's scale and opacity in percent), with the expressions it reads evaluated first. The samples are fitted into keys that replace those under it; a constant becomes a still value, source text sets the text. The report says, per expression, its engine, frames, keys before and after and largest error, or why it was not baked. Projects now record their expression engine (`ExEn`).
- `motion export <scene> --project <file.aep> --out <file.aep>` writes an edited scene back into the project it was imported from (D45): each changed static value the project stores (numbers, points, scales, opacities, colours, effect parameters) is patched into its bytes, every other byte is kept, and the patched project is read back and imported before it is saved. An unedited scene exports to the original file byte for byte. Every other change is reported with why it is not written back (a default, an expression, keys, text, a new layer).
- The import report keeps each expression's whole source, and every expression control with its values, for live links (D44).
- Curve families: `<shape>-<family>` names, such as `out-expo` or `in-out-quint`, with shapes `in`, `out`, `in-out` and `out-in`, and families `quad`, `cubic`, `quart`, `quint`, `sine`, `circ`, `expo`, `back`, `elastic` and `bounce`. Parameters go in parentheses: `in-out(2.5)`, `out-back(2)`, `out-elastic(1.2,.4)`. Also `steps(n)` and `steps(n,start)`. They are evaluated exactly at every frame, and behaviours take them too (`pop 18f out-back(2)`).
- Spring curves: `spring(bounce)` and `spring(bounce,perceived)`, a damped spring released from rest that settles on the end value, overshooting for a bounce above 0. In a key span it is scaled to the span. A behaviour without a duration lasts until it rests (`pop spring(.4,10f)`), and that settle time is solved exactly rather than by stepping.
- Labels and relative times: a composition's `labels` name moments of its timeline (`"cta":"6s"`, `"outro":"cta+2s"`), and a layer's `offset` and `span` may be written against a label, `<` (where the layer before ends) or `<<` (where it starts), moved by a time (`"span":"intro-cta"`, `"offset":"<-6f"`). They resolve when the scene is read, and `Comp::labels` keeps the resolved labels.
- Relative values and value lists: a key may be written against the property's resting value (`rest`, `rest+40`, `rest-0,40`, `rest*1.2`), resolved after layout so the move follows the layer, and the string form chains values (`"0 -> 200@40% -> 150 @0-30f"`) that split the span evenly unless a value says where it falls.
- Stagger on text parts: a text animator's `stagger` lets the parts counted by `by` take turns, each seeing the animator, selectors included, as it was its wait earlier, in `order` (`first`, `last`, `center`, `edges`, or `random` by `seed`). A text layer's `in` takes a part word, `stagger <time>` and an order (`"fade-up word 10f out-back stagger 3f"`) and becomes such an animator, so each part makes the whole entrance with its own curve.
- Trim: a `trim` shape item cuts the outlines listed before it, those in earlier groups included, down to a stretch from `start` to `end`, moved by `offset` in degrees, each on its own or `joined` as one line in order. Every paint that draws a cut outline draws the cut one, and inner groups' trims cut first. The import maps trim paths onto it (65 of the 241 local sample projects use them).

### Changed

- `glow` holds a colour's Rec. 709 luma against its threshold (`nakkash_raster::GLOW_LUMA`), not its Rec. 601 luma ([evidence G3](docs/design/aep-evidence.md#glows)). - A composition shown by several layers at the same time is drawn once a frame. The engine makes its children once per composition and frame of its clock and marks the layers that show it with one `Shared` mark (`Layer::shared`). The rasteriser draws marked children once for each transform and canvas size, and keeps the drawing until the last marked layer has used it. Frames are byte for byte the same. The engine shares one node per read layer of a composition (`Effect::with_input` takes an `Arc<Node>`), and the rasteriser keeps its drawing for each transform and canvas size it is read at, letting it go after its last counted read. Frames are byte for byte the same. Effects, laying layers on the float canvas, masks, mattes, clips, motion blur of a drawing and laying planes split their pixels into runs of rows; frames are the same bits on one thread and on many. - Precise frames draw a shrunk layer whose effects read only a few px where it lands at its own size, and lay it down ([D76](docs/design/decisions.md#d76-a-composition-is-drawn-at-the-size-it-lands-at)). - `nakkash edit` and `check` are fast on large scenes. On a 4K template imported with 6,159 layers at any depth and a 796,356-line report, one edit took more than ten minutes and now takes about 3 s of processor time, the edit's own check 0.4 s for an edit of one instance ([D79](docs/design/decisions.md#d79-an-edit-checks-only-what-it-can-change)):
  - `Report::since` compares with a baseline in time proportional to the two reports (it compared every violation with every other, which took the ten minutes);
  - `check` evaluates frames side by side on the threads a render may use, then hands each layer its frames in order, so the report is the same to the bit on any number of threads; it builds each layer's address once, and text on text passes over glyphs and texts that cannot meet;
  - a check is kept (`Checked`): after an edit, only the layers the edit can change are read again, found by comparing the compiled scenes instance by instance, and the session keeps the version before, so `edit`, `batch` and variants start from the check they already have. A test holds the kept check to a check from scratch over random edits of every corpus scene and example;
  - a layer id shares its text, so a report's addresses cost no copies.
- The `contrast` gate measures each readable text at each sample on its own thread, where it measured the samples on one thread each: a 4K template with 792 readable text instances at 4 samples kept 4 threads busy, and now has 3,168 pieces of work for every thread. When `flash` has drawn every frame whole, a text whose glyphs cover less than a px is passed over without drawing what is behind it, which it was never measured against. The report, and which failure is reported first, are the same.
- The project is renamed from motion to **nakkash**, after the classical miniature painters who illuminated manuscripts ([D73](docs/design/decisions.md#d73-the-project-is-named-nakkash)): the crates are `nakkash-*` (Rust paths `nakkash_*`, so log filters and targets such as `nakkash::timings` change too), the command is `nakkash`, new scenes write `"nakkash": 1`, the variables are `NAKKASH_LOG` and `NAKKASH_CACHE`, the font cache's folder is `nakkash`, and the agent skill lives in `skills/nakkash`. Every example and fixture, and the compatibility corpus, write the new key; a test reads each corpus scene under the old key too and finds the same scene.
- `motion edit` prints what the edit added to the scene's check, against the scene before it, and exits 1 only when the edit made a new error. It printed the whole check, so a correct edit of a template with errors of its own exited 1.
- Encoding is about three times as fast for light scenes: the colour conversion reads each pixel once and converts bands of rows in parallel, 3.3 ms for a 1080p frame instead of 11.1 ms, with every sample the same. 60 frames of the launch example render to H.264 in 0.3 s.
- `--video-quality web` asks the system's H.264 and HEVC encoders for quality 0.8, up from 0.65: dark gradients no longer turn into blocks with coloured blotches (the 99th-percentile error on the demo film's night sky falls from 3.0 levels to 1.26), for about half again the size. The speed and size table in `rendering.md` is measured again, all of it one way.
- Reports name layers by address ([D43](docs/design/decisions.md#d43-one-layer-address-and-edits-per-instance)): `StoredText::layer` and `TextCheck::layer` are an `Address` where the scene writes the layer (`title`, or `scene.comps.card.layers[title]`), replacing `comp` and `layer`. `diff --ignore` and the fidelity manifest's `ignore` take addresses, so `card/photo` hides a layer in one instance. The import's own path `Step` is gone: sources use `motion_format::Step`, `address::json_at` and `address::key_text`, which the edit crate and `Place` share too.
- The variants design reads as motion works now ([D43](docs/design/decisions.md#d43-one-layer-address-and-edits-per-instance)): the project is imported directly, expressions are baked, instances of a composition are edited one at a time, and a variant can be patched back into its project. The glossary gains address, instance and override.
- Edits take a layer's address ([D43](docs/design/decisions.md#d43-one-layer-address-and-edits-per-instance)): `card/title text="Sale"` writes `overrides` on `card` for that instance alone, starting a change inside a key from the key as the instance draws it. A key path may pick a list element by id or index, `fx[glow].radius` or `scene comps.label.layers[title].text=Hi`. `none` through an instance takes back its own value, and refuses a key its composition gives. `Edit::target` is an `Address`, and `KeyPath` has steps instead of segments. `check` gives fix hints for inner layers as edits of their instance.
- `check` and `at` reach every layer at any depth ([D43](docs/design/decisions.md#d43-one-layer-address-and-edits-per-instance)): a layer inside a composition is checked in scene space and reported by its address, `card/title`, measured by what its compositions' clips let it draw. `motion at` takes addresses, and lists every layer at any depth when given none. `Violation::id` is now `Violation::address`.
- `motion import` clamps a value outside its property's range into it, as the original draws it, instead of failing: a wiggled opacity past 100%, a negative roundness, colour channels above 1. Expression samples are clamped frame by frame before the fit; the report lists each clamp under `clamped`.
- The scene's root is a composition ([D43](docs/design/decisions.md#d43-one-layer-address-and-edits-per-instance)): `Scene::root` and `SceneGraph::root` hold its canvas, clock, background and layers, and one function validates and compiles the root and every composition under `comps`.
- A diagnostic's path is a `Place` ([D43](docs/design/decisions.md#d43-one-layer-address-and-edits-per-instance)): an `Address` inside the scene, or text for places outside it. Errors name a layer by its id, as edits and queries do: `title.in`, not `layers[0].in`. A layer whose id is missing or shared is still named by its index.
- `motion export` compares what it reads back with the edit in the import's six-decimal steps, allowing one, so a value half a step from both neighbours no longer fails the check.
- Baking expressions sits behind `motion-import`'s `bake` feature, which only the CLI turns on: `motion-engine` renders and imports without linking the script engine. The D38 and D39 guards check each crate's resolved dependencies (`cargo tree`), not its manifest lines.
- The bake eases the values it reads with the scene's own curves and motion paths (`motion_scene::Ease`, `PathSpan`), not a copy of them.
- An expression that reads nothing that changes with time runs once, not at every frame: a run knows whether it read `time`, a value the host says changes, or randomness seeded by the time (`Run::constant`, `Host::constant`).
- Six crates instead of ten: the error type and shared grammar pieces live in `motion-format`, evaluation in `motion-scene`, and logging setup in `motion-engine`.
- `check` evaluates one frame at a time instead of keeping every frame in memory.
- Error messages name the path and the accepted form, with an example, for every syntax and unknown-name error.
- Shorthands (size, time, colour, rect, font, position, curves, `in`, `anim` tracks) are read by `winnow` grammars.
- The scene is read with a serde document, so errors in its shape carry the path of the value.
- Edit paths use a real grammar, so `card anim.opacity="0 -> 1 @0-12f"` and JSON values (`anim={...}`) are read by `serde_json`.
- Quiet by default: nothing is logged unless `--log` or `MOTION_LOG` asks for it, and a failing run prints only its `error:` line.
- `motion diff` and `motion fidelity` measure a third window, `content`: where the scene draws or the reference differs from the scene's background by more than the tolerance, so content the scene fails to draw counts against it. It is the headline number in their output, their JSON and the ledger, and the ledger's regression check counts it; `DiffOptions` takes the layers to ignore, and the diff leaves out where they draw ([D42](docs/design/decisions.md#d42-fidelity-is-headlined-over-the-reference-content)).

- `at` prints only the properties that differ from their default after `x y w h`.
- The property `x` and `y` are now the components of `position`; `scale` is a point (`scale=0.8,0.8` in `at`); `at` places the layer's anchor, which rests at the centre of its box, so existing scenes draw as before.
- `check` fix hints skip axes driven by `anim`.
- Properties live in one registry per kind of object (`LAYER`, `GROUP`, and one per shape item and effect); unknown-property errors name the kind (`unknown layer property`).
- A layer with two content keys reports the conflict at the second key.
- Text is set with `motion-text` at compile time, so boxes, `at` and `check` measure real glyphs; `compile` takes a `Typesetter` and returns a `Result`, and `ApproxTextMeasure` is gone. - Layer `fill` takes any colour form, including `[r, g, b, a]` from 0 to 1.
- `NodeState` carries what a node draws (`content`, `local_bounds`, `fill`, `fx`, `hidden`); `check` ignores hidden layers.

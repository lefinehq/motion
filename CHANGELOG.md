# Changelog

All notable changes to this project are documented here. The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this project follows [Semantic Versioning](https://semver.org/).

## [Unreleased]

### Added

- `Address::written`, `Address::written_in_comp`, `Scene::find` and `SceneGraph::find`: a layer named where the document writes it, in the scene or in a composition. An `Address` reads from and writes to JSON as its text.
- `Scene::layer`, `Scene::drawn` and `Scene::addresses`, `Document::layer_json` and `motion_format::overrides`: a layer at any depth as drawn, typed or as JSON, with the overrides on the way set over it. `motion_format::address::key_path` reads a key path on its own.
- `overrides` on a `comp` layer ([D43](docs/design/decisions.md#d43-one-layer-address-and-edits-per-instance)): layer keys by address, set over the layers of the composition it draws for that layer alone, `{"title":{"text":"Sale"},"badge/icon":{"fill":"#E63946"}}`. The result is validated as any layer is, errors point at the inner layer (`card/title.text`), and each such layer compiles to a composition of its own. `Content::Comp` holds a `CompContent`.
- `motion_scene::walk`: every node of an evaluated frame at any depth, in paint order, with its address, its transform in scene space, its opacity, the clip of the compositions around it and whether it draws. `SceneGraph::paths` lists the same nodes for every frame.
- `motion_format::Address` and `Id` ([D43](docs/design/decisions.md#d43-one-layer-address-and-edits-per-instance)): one grammar and printer for a layer at any depth and the keys inside it (`card/title.fx[glow].radius`). The id rule lives in `Id` instead of a hand-written loop. `scene` is reserved: a layer may not take it, and the import gives such a layer `scene-2`.
- Cargo workspace, repository documents and CI.
- `motion-format`: time, colour and size shorthand parsing, and `fmt_num`.
- First slice: scene format, check, at, edit.
- `motion-scene`: compile a scene into a graph of laid-out layers.
- Evaluate a scene graph at any frame.
- `motion-query`: `check` and `at` over a scene graph.
- `motion-edit`: a one-line edit language for scenes.
- `motion-cli`: the `motion` tool with `check`, `at` and `edit` commands.
- Curves as a table of names plus `cubic(x1,y1,x2,y2)` and `hold`, usable on any property.
- A property registry (`x`, `y`, `opacity`, `scale`, `rotate`) with a default and a range for each.
- Presets as data (`fade`, `fade-up`, `fade-down`, `fade-left`, `fade-right`, `pop`, `spin-in`), and a scene `presets` key to add or override them.
- `anim` tracks, as a one-line string or a keyframe list, with a curve per key; `anim` and `in` may not animate the same property.
- `scale` and `rotate` are evaluated, and `check` measures the transformed bounding box.
- Nested edit paths (`card anim.opacity=...`), JSON values in edits, and removal of objects left empty by `none`.
- Tooling: `proptest` parser tests, `insta` snapshots, coverage and `cargo-deny`.
- One error type, `Diagnostic`, with a kind (syntax, unknown name, out of range, missing, conflict, wrong type, invalid, io) that sets the exit code.
- `motion-engine`: a `Session` that is the one entry point for tools, and `motion-cli` now goes through it.
- Logs with `--log <level>`, `--log-format json` and `MOTION_LOG`, and step timings with `--timings`.
- `motion-import`: reads `.aep` projects (items, compositions, footage, layers, the property tree, keyframes, expressions and paths) into a typed model, keeps what it cannot decode yet as opaque values with a reason, and counts everything in an import report.
- `motion inspect <project.aep>` prints a project as a tree with its import report, or both as JSON with `--json`; the engine reads projects with `motion_engine::import`.
- `motion-import` decodes text documents (text, paragraph and character runs with resolved style sheets, point or box frame, and the line layout the project stored) with a `winnow` grammar for their object syntax and serde records over it, and 3D orientation angles; neither is opaque any more.
- `motion_format::grammar::parse_at`, which also hands the failing offset to the explanation; `parse_all` now takes any `winnow` input, bytes included.
- Typed property values (number, point, colour) and the transform set `position` (components `x`, `y`), `anchor`, `scale` (one number or `[x, y]`), `rotate` and `opacity`; any property can rest at a value set by its name on the layer.
- Keys ease in value space: `speed(out,out-reach,in,in-reach)` holds any ease, including a span between equal keys; a point that moves in space follows a bézier path (`"path"` on an object key) at a pace measured along it; other points can take one curve per component.
- Layers can follow a `parent`, show only in their `span`, and run on their own time with `offset` and `stretch`.
- Shape layers: `shapes` lists items (`group`, `rect`, `ellipse`, `path`, `fill`, `stroke`), each written as an object keyed by its kind with its own property registry, settings (fill `rule`, stroke `cap` and `join`), `anim` tracks, optional `id` and `hidden`. Paints cover the outlines before them in their group, through nested groups' transforms; `motion-scene` evaluates them into draws, back to front, and measures their bounds.
- Path values: SVG path data (`M`, `L`, `C`, `Z`) as a property type that tracks morph vertex by vertex.
- Effects: an `fx` list on any layer, in the same item form; `fill` is the first effect.
- Compositions: a scene `comps` map with its own size, clock, length and background, drawn by `comp` layers at the layer's own time; cycles are rejected. `pivot` layers draw nothing and carry a transform for children. Layers can be `hidden`.
- The canonical writer puts each composition's layers one per line too.
- Text animators: `animate` on text layers lists animators whose key holds `range` selectors (by `char`, `char-no-space`, `word` or `line`; `start`, `end`, `offset`, `amount`, `smooth`; six shapes and six modes). Each glyph takes the animator's `position`, `anchor`, `scale`, `rotate`, `opacity`, `fill`, `stroke`, `stroke-width` and `tracking` scaled by how much it is chosen; `motion-scene` evaluates them per glyph, and `check` measures where the visible glyphs are.
- An item kind's key may hold a setting (a selector's `by`) or items of another table (an animator's selectors).
- Rendering: `motion-engine` maps an evaluated frame to `motion-raster`'s display list (layer transforms, opacity and visibility; rect layers; shape fills and strokes with their rules, caps, joins and miters; text runs with fill, stroke and paint order, per glyph under animators; faux bold as a fill-coloured stroke and faux italic as a 12° slant; nested compositions as clipped, isolated layers over their background; `fx` joined by name to the rasteriser's effects). `Session::display_list`, `render`, `render_with`, `frames` and `render_frames`, which draws a range on every thread.
- `motion render <scene> [--frames A-B | --frame N] --out <dir> [--quality fast]` writes `frame-00000.png` files.
- Golden images of whole scenes in `motion-engine` (shapes, text under an animator, faux styles, nested compositions, the fill effect), and a release timing of a 1080x1920 story scene through every step.
- Text style: a scene `fonts` list; on text layers `style` (fill, stroke, stroke width and paint order, tracking, leading, baseline shift, caps, faux bold and italic, italic faces; alignment, indents and paragraph spacing), `runs` over character ranges, `paragraphs`, and `box` for box text. The keys are one table in `motion_format::text`.
- `motion-raster`: draws a frame's display list (layers with transform, opacity, blend mode, clip and effects; filled and stroked paths; glyph runs) into an RGBA image with `vello_cpu`, and writes PNG files. Seventeen blend modes, caps, joins and fill rules are tables; the `fill` effect is the first row of the effect registry. Golden images are drawn with portable scalar code so they compare exactly across machines.
- `motion-text`: a font set read from given files and folders (by PostScript name, or family, weight and slant; every named instance of a variable font; Inter built in), and text layout with Parley and HarfRust: paragraphs, character runs, point and box text, every justification, indents, paragraph spacing, leading, tracking, baseline shift and capitals, into lines with cumulative character advances and glyph runs ready for `vello_cpu`. A missing font or glyph is an error.

- `motion-fonts`, `motion fonts fetch` and `motion import --fetch-fonts`: the fonts a scene lacks are found in open-licensed sources (each family's repository and Google Fonts), pinned in a lock beside the scene and kept in a content-addressed cache. For an import, each family takes the release whose glyph ids and widths match the project's stored text. A lock in a scene's `fonts` loads its faces from the cache and checks their hashes; a render never fetches (D39).
- The text check compares glyph ids with those the project stored, and the import report says when they differ.
- Font fallback at import: a font the import does not have is replaced by the closest available face (the same family, else the built-in Inter, at the same slant and nearest weight; a missing font's style is read from its PostScript name's suffix), and each use is reported as `missing fonts, substituted (`<font> → <face>`)`. `motion import` and `motion fidelity` substitute; scenes written by hand still fail on an unknown font ([D40](docs/design/decisions.md#d40-missing-fonts-are-substituted-at-import)).
- Quoted edit values take `\n` (new line) and `\t` (tab) escapes besides `\"` and `\\`, so `title text="Make\nit move"` sets two lines.
- Image layers: `"image":"photos/beach.jpg"` with a `box` draws a PNG or JPEG file stretched over the box, relative to the scene file. The engine decodes each file once, when a frame first shows it; `motion-raster` gains `Picture` and the `ImageDraw` leaf, decoding PNG with `png` and JPEG with `zune-jpeg` ([D41](docs/design/decisions.md#d41-image-layers-name-their-file-and-carry-their-box)).
- The import draws still footage: it looks for each footage file where the project stored it, then by name under the project's folder, and writes the pictures it finds as image layers. Footage it cannot find, video, image sequences and audio are reported with why. `motion_engine::import_scene` takes where the scene will be saved, so footage paths are relative to it.

- `motion-expr`: expressions compile once and run at any time over a host (comps, layers, properties, keys), with the language's array arithmetic, interpolation, loops, vector and colour functions, the legacy engine's forms, deterministic maths and randomness, and a fitter that turns per-frame samples into a few keys within a tolerance. Every distinct expression of the local corpus compiles (D38).
- `motion import` bakes expressions (D38): each one switched on is evaluated at every frame its layer shows, where the scene shows its comp, over the project read as the language sees it (comps, layers, groups, properties, effect parameters at their default, a layer's scale and opacity in percent), with the expressions it reads evaluated first. The samples are fitted into keys that replace those under it; a constant becomes a still value, source text sets the text. The report says, per expression, its engine, frames, keys before and after and largest error, or why it was not baked. Projects now record their expression engine (`ExEn`).
- `motion export <scene> --project <file.aep> --out <file.aep>` writes an edited scene back into the project it was imported from (D45): each changed static value the project stores (numbers, points, scales, opacities, colours, effect parameters) is patched into its bytes, every other byte is kept, and the patched project is read back and imported before it is saved. An unedited scene exports to the original file byte for byte. Every other change is reported with why it is not written back (a default, an expression, keys, text, a new layer).
- The import report keeps each expression's whole source, and every expression control with its values, for live links (D44).
- Curve families: `<shape>-<family>` names, such as `out-expo` or `in-out-quint`, with shapes `in`, `out`, `in-out` and `out-in`, and families `quad`, `cubic`, `quart`, `quint`, `sine`, `circ`, `expo`, `back`, `elastic` and `bounce`. Parameters go in parentheses: `in-out(2.5)`, `out-back(2)`, `out-elastic(1.2,.4)`. Also `steps(n)` and `steps(n,start)`. They are evaluated exactly at every frame, and behaviours take them too (`pop 18f out-back(2)`).
- Spring curves: `spring(bounce)` and `spring(bounce,perceived)`, a damped spring released from rest that settles on the end value, overshooting for a bounce above 0. In a key span it is scaled to the span. A behaviour without a duration lasts until it rests (`pop spring(.4,10f)`), and that settle time is solved exactly rather than by stepping.
- Labels and relative times: a composition's `labels` name moments of its timeline (`"cta":"6s"`, `"outro":"cta+2s"`), and a layer's `offset` and `span` may be written against a label, `<` (where the layer before ends) or `<<` (where it starts), moved by a time (`"span":"intro-cta"`, `"offset":"<-6f"`). They resolve when the scene is read, and `Comp::labels` keeps the resolved labels.
- Relative values and value lists: a key may be written against the property's resting value (`rest`, `rest+40`, `rest-0,40`, `rest*1.2`), resolved after layout so the move follows the layer, and the string form chains values (`"0 -> 200@40% -> 150 @0-30f"`) that split the span evenly unless a value says where it falls.
- Stagger on text parts: a text animator's `stagger` lets the parts counted by `by` take turns, each seeing the animator, selectors included, as it was its wait earlier, in `order` (`first`, `last`, `center`, `edges`, or `random` by `seed`). A text layer's `in` takes a part word, `stagger <time>` and an order (`"fade-up word 10f out-back stagger 3f"`) and becomes such an animator, so each part makes the whole entrance with its own curve.
- Trim: a `trim` shape item cuts the outlines listed before it, those in earlier groups included, down to a stretch from `start` to `end`, moved by `offset` in degrees, each on its own or `joined` as one line in order. Every paint that draws a cut outline draws the cut one, and inner groups' trims cut first. The import maps trim paths onto it (65 of the 241 local sample projects use them).

### Changed

- Reports name layers by address ([D43](docs/design/decisions.md#d43-one-layer-address-and-edits-per-instance)): `StoredText::layer` and `TextCheck::layer` are an `Address` where the scene writes the layer (`title`, or `scene.comps.card.layers[title]`), replacing `comp` and `layer`. `diff --ignore` and the fidelity manifest's `ignore` take addresses, so `card/photo` hides a layer in one instance. The import's own path `Step` is gone: sources use `motion_format::Step`, `address::json_at` and `address::key_text`, which the edit crate and `Place` share too.
- The variants design reads as motion works now ([D43](docs/design/decisions.md#d43-one-layer-address-and-edits-per-instance)): the project is imported directly, expressions are baked, instances of a composition are edited one at a time, and a variant can be patched back into its project. The glossary gains address, instance and override.
- Edits take a layer's address ([D43](docs/design/decisions.md#d43-one-layer-address-and-edits-per-instance)): `card/title text="Sale"` writes `overrides` on `card` for that instance alone, starting a change inside a key from the key as the instance draws it. A key path may pick a list element by id or index, `fx[glow].radius` or `scene comps.label.layers[title].text=Hi`. `none` through an instance takes back its own value, and refuses a key its composition gives. `Edit::target` is an `Address`, and `KeyPath` has steps instead of segments. `check` gives fix hints for inner layers as edits of their instance.
- `check` and `at` reach every layer at any depth ([D43](docs/design/decisions.md#d43-one-layer-address-and-edits-per-instance)): a layer inside a composition is checked in scene space and reported by its address, `card/title`, measured by what its compositions' clips let it draw. `motion at` takes addresses, and lists every layer at any depth when given none. `Violation::id` is now `Violation::address`.
- `motion import` clamps a value outside its property's range into it, as the original draws it, instead of failing: a wiggled opacity past 100%, a negative roundness, colour channels above 1. Expression samples are clamped frame by frame before the fit; the report lists each clamp under `clamped`.
- The scene's root is a composition ([D43](docs/design/decisions.md#d43-one-layer-address-and-edits-per-instance)): `Scene::root` and `SceneGraph::root` hold its canvas, clock, background and layers, and one function validates and compiles the root and every composition under `comps`.
- A diagnostic's path is a `Place` ([D43](docs/design/decisions.md#d43-one-layer-address-and-edits-per-instance)): an `Address` inside the scene, or text for places outside it. Errors name a layer by its id, as edits and queries do: `title.in`, not `layers[0].in`. A layer whose id is missing or shared is still named by its index.
- `motion export` compares what it reads back with the edit in the import's six-decimal steps, allowing one, so a value half a step from both neighbours no longer fails the check.
- Baking expressions sits behind `motion-import`'s `bake` feature, which only the CLI turns on: `motion-engine` renders and imports without linking the script engine. The D38 and D39 guards check each crate's resolved dependencies (`cargo tree`), not its manifest lines.
- The bake eases the values it reads with the scene's own curves and motion paths (`motion_scene::Ease`, `PathSpan`), not a copy of them.
- An expression that reads nothing that changes with time runs once, not at every frame: a run knows whether it read `time`, a value the host says changes, or randomness seeded by the time (`Run::constant`, `Host::constant`).
- Six crates instead of ten: the error type and shared grammar pieces live in `motion-format`, evaluation in `motion-scene`, and logging setup in `motion-engine`.
- `check` evaluates one frame at a time instead of keeping every frame in memory.
- Error messages name the path and the accepted form, with an example, for every syntax and unknown-name error.
- Shorthands (size, time, colour, rect, font, position, curves, `in`, `anim` tracks) are read by `winnow` grammars.
- The scene is read with a serde document, so errors in its shape carry the path of the value.
- Edit paths use a real grammar, so `card anim.opacity="0 -> 1 @0-12f"` and JSON values (`anim={...}`) are read by `serde_json`.
- Quiet by default: nothing is logged unless `--log` or `MOTION_LOG` asks for it, and a failing run prints only its `error:` line.
- `motion diff` and `motion fidelity` measure a third window, `content`: where the scene draws or the reference differs from the scene's background by more than the tolerance, so content the scene fails to draw counts against it. It is the headline number in their output, their JSON and the ledger, and the ledger's regression check counts it; `DiffOptions` takes the layers to ignore, and the diff leaves out where they draw ([D42](docs/design/decisions.md#d42-fidelity-is-headlined-over-the-reference-content)).

- `at` prints only the properties that differ from their default after `x y w h`.
- The property `x` and `y` are now the components of `position`; `scale` is a point (`scale=0.8,0.8` in `at`); `at` places the layer's anchor, which rests at the centre of its box, so existing scenes draw as before.
- `check` fix hints skip axes driven by `anim`.
- Properties live in one registry per kind of object (`LAYER`, `GROUP`, and one per shape item and effect); unknown-property errors name the kind (`unknown layer property`).
- A layer with two content keys reports the conflict at the second key.
- Text is set with `motion-text` at compile time, so boxes, `at` and `check` measure real glyphs; `compile` takes a `Typesetter` and returns a `Result`, and `ApproxTextMeasure` is gone. A text layer's own coordinates start at its first baseline, and its box is the layout's bounds. The built-in font's family is `Inter Variable`.
- Layer boxes are rectangles (`kurbo::Rect`): rests and `at` resolve in them. `Session::graph`, `frame` and `check` return a `Result`, and the session has a `fonts` step.
- Layer `fill` takes any colour form, including `[r, g, b, a]` from 0 to 1.
- `NodeState` carries what a node draws (`content`, `local_bounds`, `fill`, `fx`, `hidden`); `check` ignores hidden layers.
- Unit tests moved out of `src/` into `tests/unit`, mirroring the source tree.
